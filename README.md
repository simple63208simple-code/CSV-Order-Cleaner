# CSV Order Cleaner

Консольная программа на Python для проверки CSV с заказами. Удаляет повторяющиеся записи, отделяет ошибки, считает сумму заказов и сохраняет отчёт. Использует только стандартную библиотеку Python; установка дополнительных пакетов не нужна.

## Запуск

Нужен Python 3.9 или новее. Откройте терминал в папке проекта:

```sh
python main.py examples/orders.csv
```

На macOS/Linux вместо `python` может требоваться `python3`.
Без аргумента (`python main.py`) программа попросит ввести путь. Относительные пути считаются от текущей папки терминала.

Можно выбрать папку результатов:

```sh
python main.py examples/orders.csv --output-dir results
```

Каждый запуск создаёт новую папку `results/run-...` и выводит её полный путь. Предыдущие результаты и исходный файл не перезаписываются.

## Формат и правила

- CSV в UTF-8 (также поддерживается UTF-8 с BOM), разделитель — запятая.
- Обязательные столбцы: `name`, `product`, `price`. Дополнительные столбцы сохраняются.
- Названия столбцов должны быть непустыми и уникальными. Регистр учитывается.
- Пробелы по краям названий столбцов и значений удаляются.
- Имя и товар не могут быть пустыми.
- Цена: неотрицательное число, максимум два знака после точки; например `800`, `800.5`, `800.50`. Ноль разрешён. Знаки валют, экспоненциальная запись и десятичная запятая не поддерживаются.
- Все суммы должны быть в одной валюте. Расчёт ведётся точно в целых сотых единицы, вывод — с двумя знаками после точки.
- Дубликат — совпадение **всех** полей после очистки пробелов и приведения цены к единому виду. Поле `date`, если присутствует, тоже участвует в сравнении. Сохраняется первая запись.
- Пустые физические строки пропускаются. Строки с неверным числом полей сохраняются как ошибки.
- Запятые и переводы строк внутри поля поддерживаются при правильном CSV-экранировании кавычками.

Пример:

```csv
name,product,price,date
Олег,Мышка,800.50,2026-10-28
```

## Результат

В новой папке появляются:

- `clean_orders.csv` — корректные уникальные записи с очищенными значениями.
- `invalid_orders.csv` — `line_number` (начальная физическая строка записи, заголовок — строка 1), `error` (первая найденная ошибка), `original_fields` (исходные значения полей в виде JSON-массива, включая лишние поля).
- `report.txt` — число записей, дубликатов и ошибок, сумма корректных уникальных заказов.

Для `examples/orders.csv` ожидается:

```text
===== ОТЧЁТ =====
Всего заказов: 9
Количество дубликатов: 1
Уникальных заказов: 5
Выручка без дубликатов: 16800.00
Количество неправильных записей: 3
```

Эталонные файлы находятся в `examples/expected/`.

## Проверка

Из папки проекта:

```sh
python -m unittest discover -s tests -v
```

Тесты проверяют пример, заголовки, цены, точность суммы, дубликаты с разными датами, пробелы, BOM, повреждённые строки, CSV с кавычками, сохранение результатов и ошибки доступа.

## Ограничения

Одинаковые реальные покупки невозможно надёжно отличить от повторов без идентификатора заказа. Если в данных есть `order_id`, он участвует в сравнении как обычный столбец; проверка конфликтов одного ID не выполняется. Даты сохраняются как текст, их формат не проверяется. Выручка означает сумму поля `price`, без учёта количества товара, возвратов и статуса оплаты.

Повреждённая структура CSV (например, незакрытые кавычки), неверная кодировка или заголовок останавливают обработку с сообщением об ошибке; результаты такого чтения не сохраняются. При ошибке записи может остаться неполная папка результатов, её путь указан в сообщении. Программа хранит записи в памяти и рассчитана на небольшие файлы. Дубликаты учитываются в отчёте, но отдельный файл с ними не создаётся.
